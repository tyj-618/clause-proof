## 目标

实现 `judge` 模块的判定逻辑：把 Query 构造成提示词、调用模型、把输出解析为 Judgment。
解析失败一律降级为「模糊」，**不抛异常**。

## 验收标准

**提示词（build_prompt）**

- [ ] system 与 user 分工明确：system 定角色与输出格式，user 给材料与任务
- [ ] user 中包含：合同全文、该条款的英文原名、以及 §3.2 中**该类条款的三态边界说明**
- [ ] 明确要求 `quotes` 必须是**从原文逐字复制的连续片段**，不得改写、省略、加省略号或加引号
- [ ] 明确要求输出 JSON：`{"present": "...", "quotes": [...], "confidence": 0.0}`
- [ ] 明确 `present` 只能取 `present` / `absent` / `uncertain`
- [ ] 明确「判定为 uncertain 时 quotes 可以为空」
- [ ] 提示词中不出现任何 gold span（测试断言字符串里也不出现 gold 的原文）
- [ ] 六类条款的边界说明各来自 PRD §3.2，不得增删语义

**解析（parse_response）**

- [ ] 能解析：裸 JSON、```json 围栏、前后带说明文字的 JSON（取首个 `{` 到末个 `}`）
- [ ] 下列情形一律返回 `parse_ok=False`、`present=UNCERTAIN`、`confidence=0.0`、`quotes=()`，**不抛异常**：
  - 非 JSON 文本
  - 缺任一必需字段
  - `present` 取值不在三值内
  - `confidence` 非数字、为布尔、或越界（<0 或 >1）
  - `quotes` 不是字符串数组
  - `present=absent` 但 `quotes` 非空（违反 Judgment 不变式）
- [ ] 正常情形 `parse_ok=True`，字段值与 JSON 一致
- [ ] 对同一输入两次调用返回相等对象（纯函数性质）

**集成（LLMJudge）**

- [ ] `judge()` 调用 `client.complete`，把 `Completion` 映射为 `CallMeta`（六个字段全部落位）
- [ ] `LLMClient` 抛出的 `RuntimeError` **不捕获**，直接上抛（由 runner 转失败记录）
- [ ] judge 层不做重试、缓存、成本计算
- [ ] 提示词构造与解析不依赖 `LLMClient`

**工程**

- [ ] 全部测试用 `FakeTransport`，不发真实网络请求
- [ ] `make check` 全绿
