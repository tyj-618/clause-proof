## 验收标准

**配置**

- [ ] 环境变量优先于 `.env` 文件
- [ ] 缺少 `ANTHROPIC_BASE_URL` 或 `ANTHROPIC_AUTH_TOKEN` 时抛 `RuntimeError`，消息说明缺哪一项以及怎么补
- [ ] `prices_for` 对未知模型抛 `RuntimeError`，不返回 0

**缓存**

- [ ] 同一 prompt + 同一参数，第二次调用不发起任何请求（传输层调用计数为 0），返回 `cached=True`
- [ ] 缓存键包含 model、system、prompt、max_tokens、temperature；任一变化都产生不同缓存键
- [ ] 缓存写入后，重新构造 `LLMClient` 仍能命中（跨进程可用）

**重试**

- [ ] 传输层抛 429 或 5xx 时重试，最多 `max_retries` 次，退避时间递增
- [ ] 重试后成功则返回正常结果，并记录实际尝试次数
- [ ] 重试耗尽仍失败时抛 `RuntimeError`，消息包含最后一次的错误原因
- [ ] 4xx（除 429）不重试，立即抛 `RuntimeError`

**计量**

- [ ] 从响应的 `usage` 提取 input / output / cached input tokens
- [ ] `cost_cny` = 输入 × 单价 + 输出 × 单价，按百万 tokens 折算
- [ ] `latency_ms` 记录本次调用（含重试）的墙钟时间

**输出异常**

- [ ] `stop_reason == "max_tokens"` 且正文为空时抛 `RuntimeError`，
      消息提示「模型可能在思考阶段耗尽预算，请提高 max_tokens」

**安全**

- [ ] 任何异常消息与日志中都不出现 `api_key`（用假 key 断言）
- [ ] 默认不打印 prompt 正文；需要调试时只打印 `prompt_hash`

**工程**

- [ ] 全部测试使用 `FakeTransport`，不发起真实网络请求
- [ ] `make check` 全绿
