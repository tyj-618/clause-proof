# T-006 协议抽象与端点切换

- 状态：待实现
- 分支：feat/protocol
- 上游：docs/design/0003-interfaces.md §10；ADR-0004（上下文修正）；tasks/T-005.md 的冒烟结果

## 背景

T-005 冒烟暴露：`reasoning_effort` 在 Anthropic 兼容端点上被静默忽略，实际恒为 max 档，
导致 18 条里 5 条因思考耗尽 8192 token 而正文为空（失败率 33%），且 output 中约 90% 是思考。

实测 OpenAI 兼容端点会校验该字段（非法值返回 400，并列出合法取值），
同一 prompt 下 low 输出 3 token、max 输出 120 token。

## 目标

把请求构造与响应解析从 `LLMClient` 中抽出来，做成可替换的 `Backend`，
实现 `AnthropicBackend` 与 `OpenAIBackend`，通过配置切换，默认使用 OpenAI 协议。

## 契约

```python
# src/clauseproof/llm.py

@dataclass(frozen=True, slots=True)
class BackendResult:
    text: str
    input_tokens: int
    output_tokens: int
    cached_input_tokens: int
    stop_reason: str | None

class Backend(Protocol):
    def request(self, config: LLMConfig, prompt: str, system: str | None,
                max_tokens: int) -> tuple[str, dict, dict[str, str]]:
        """返回 (url, payload, headers)。"""

    def parse(self, response: dict) -> BackendResult:
        """把端点响应解析为统一结构。"""

class AnthropicBackend: ...
class OpenAIBackend: ...
```

`LLMClient.__init__` 增加 `backend: Backend | None = None`，默认按 `config.protocol` 选择。

`LLMConfig` 增加 `protocol: str`（`"anthropic"` | `"openai"`），由 `CLAUSEPROOF_PROTOCOL` 决定，
默认 `"openai"`。

## 字段映射

**OpenAI 请求**

```json
{
  "model": "<model>",
  "messages": [
    {"role": "system", "content": "<system>"},
    {"role": "user", "content": "<prompt>"}
  ],
  "max_tokens": 8192,
  "temperature": 0,
  "thinking": {"type": "enabled"},
  "reasoning_effort": "low"
}
```

- URL：`https://open.bigmodel.cn/api/paas/v4/chat/completions`
- 头：`Authorization: Bearer <key>`，`content-type: application/json`
- 无 system 时只有一条 user message

**OpenAI 响应**

| 统一字段 | 来源 |
|---|---|
| `text` | `choices[0].message.content`（可能为 null，按空串处理） |
| `input_tokens` | `usage.prompt_tokens` |
| `output_tokens` | `usage.completion_tokens` |
| `cached_input_tokens` | `usage.prompt_tokens_details.cached_tokens`，缺失时为 0 |
| `stop_reason` | `choices[0].finish_reason`，且 **`"length"` 归一化为 `"max_tokens"`** |

最后一条必须做：上层对空正文的保护判断用的是 `stop_reason == "max_tokens"`，
不归一化会让截断被当成正常结束。

## 验收标准

- [ ] `AnthropicBackend` 与 `OpenAIBackend` 都实现 `Backend`，`isinstance` 检查通过
- [ ] `config.protocol` 为 `"openai"` 时选 `OpenAIBackend`，为 `"anthropic"` 时选 `AnthropicBackend`，
      未知值在 `load_config` 阶段抛 `RuntimeError`
- [ ] `OpenAIBackend.parse` 正确处理：content 为 null、usage 缺 `prompt_tokens_details`、
      `finish_reason == "length"` 归一化为 `max_tokens`
- [ ] `AnthropicBackend` 的现有行为完全不变（原有测试全部通过）
- [ ] `LLMClient` 的缓存键、重试、成本、`cache_written` 行为不变
- [ ] 两种协议的请求体都由 `FakeTransport` 断言（URL、头部、payload 关键字段）
- [ ] `make check` 全绿

**reasoning_effort 取值校验**

- [ ] `openai` 协议下，`reasoning_effort` 必须属于
      `{none, minimal, low, medium, high, xhigh, max}`，否则 `load_config` 抛 `RuntimeError`
- [ ] `anthropic` 协议下保留原有的 `{low, high, max}` 校验（该端点会忽略，但不影响发送）
- [ ] openai 协议下，缺少 ANTHROPIC_BASE_URL 不报错（URL 由代码内置）
- [ ] openai 协议下，缺少 ANTHROPIC_AUTH_TOKEN 仍抛 RuntimeError
- [ ] anthropic 协议下，两者缺失都抛 RuntimeError
