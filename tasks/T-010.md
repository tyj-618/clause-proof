## 运行

**不要用 `--split report`。** 报告集全项目只有 2 次配额，留给最终版本。

```bash
caffeinate -dimsu uv run clauseproof eval \
    --split dev --n-contracts 50 --seed 42 \
    --run-id m1-baseline-dev \
    --threshold 0.8
```

- 50 份合同 × 6 类 = **300 条**
- 预计 40–60 分钟、成本约 ¥20（按 T-006 实测单条 ¥0.066、6.6–10 s 推算）
- `resume=True`：若中途意外中断，**用同一条命令重跑即可续上**，不会重复调用

## 中断与失败的处理

| 情况 | 处理 |
|---|---|
| 终端中断 / 断网 | 用同一条命令重跑，`resume` 会跳过已完成条目 |
| 部分条目 `LLM_ERROR`（网络类） | **保留记录，不删**；在报告里如实说明条数与原因 |
| 失败率 > 10% | 停下来报告，先排查原因，不要盲目重跑 |
| 熔断触发（退出码 2） | 记录触发位置与错误，报告后决定是否调整 `--max-consecutive-failures` |

**不要为了实现"干净数据"而删除失败记录。** 失败率本身就是基线的一部分，
`Report.n_failed` 就是为它准备的。
