## 三个子命令

### 1. `ask` —— 单合同演示

```bash
clauseproof ask --contract-id "<CUAD 合同标题>" --clause "Cap On Liability"
clauseproof ask --file path/to/contract.txt --clause "Governing Law"
```

- `--contract-id` 从 CUAD 加载；`--file` 从文本文件加载；二者互斥且必填其一
- `--clause` 必填，取值必须是六个 `ClauseKey` 之一（大小写不敏感，接受中文名或英文原名）
- 调用一次 `LLMJudge`，输出：判定、引用（已校验/定位失败）、置信度、路由
- **输出总行数 ≤ 40 行**

输出格式参考：

```
合同   RISEEDUCATIONCAYMANLTD_..._SERVICE AGREEMENT
条款   Cap On Liability
判定   有   confidence 0.950
路由   自动通过

引用（1 处，已校验）
  [4821:5076] EACH PARTY'S TOTAL AGGREGATE LIABILITY ARISING OUT OF ...

输入 7152 tokens · 输出 94 tokens · 耗时 6.6s · 成本 ¥0.075
```

- 引用超过 200 字符时截断并标注 `…（共 N 字符）`
- 定位失败时显示 `引用无效：该片段未在原文中找到`，并把路由强制为「转人工」

### 2. `eval` —— 批量评测

```bash
clauseproof eval --split dev --n-contracts 3 --seed 42 --run-id my-run
```

- 必填：`--split`、`--n-contracts`、`--seed`、`--run-id`
- 可选：`--out-dir`（默认 `results/`）、`--threshold`（默认 0.8，六类同值）、`--max-consecutive-failures`（默认 5）
- 构造 `RunMeta` 时 `commit` 取 `git rev-parse HEAD`，取不到写 `"unknown"`
- 结束后打印运行摘要：

```
运行 my-run 完成
  18 条 · OK 18 · 失败 0 · 模糊 4
  耗时 2m14s · 成本 ¥1.18 · 平均 6.6s/条
  JSONL  results/my-run.jsonl
  meta   results/my-run.meta.json
```

### 3. `report` —— 指标与曲线

```bash
# 只看指标（不需要阈值）
clauseproof report --run results/smoke-t006.jsonl

# 曲线：阈值必须来自另一个运行
clauseproof report --run results/smoke-t006.jsonl \
    --thresholds-from results/smoke-t005.jsonl \
    --curve --review-rates 0.25,0.5,0.75,1.0
```

- `--run` 必填；从同名 `.meta.json` 读取 `split` / `n_contracts` / `seed`，
  据此加载 gold，保证记录与 gold 严格对应
- 默认输出分类别指标表 + 宏平均 + 模糊率 + 全局 ECE
- `--curve` 需要显式提供 `--thresholds-from <另一个运行的 jsonl>`；
  **未提供时若指定 `--curve`，直接以退出码 1 报错并说明原因**

这条是硬约束，理由见下节。

## 阈值与评估集分离（本任务的核心约束）

`select_thresholds` 用 gold 判断哪些条目判错，再把它们推给人工 —— 也就是说
**阈值是"看着答案"拟合出来的**。如果在同一批数据上既拟合又评估，M4 的数字会虚高。

因此 CLI 在接口层面禁止这件事：

| 命令 | 行为 |
|---|---|
| `report`（默认） | 只算指标，不涉及阈值，不需要 gold 以外的任何东西 |
| `report --curve` | **必须**提供 `--thresholds-from`，阈值在那一批数据上拟合、应用到 `--run` 这批 |
| 不提供 `--thresholds-from` 却要曲线 | 报错退出，消息说明「阈值必须在开发集上选择」 |

并在 `docs/design/0003-interfaces.md` §3 补一句：

> `select_thresholds` 只应在开发集上调用；评估集只应用已确定的阈值，不得重新选择。
> 否则阈值会拟合到评估数据上，M4 的结果不可信。

## 退出码

严格照 `0004 §6`：

| 码 | 触发 |
|---|---|
| 0 | 成功（含 `eval` 中有单条失败但整体跑完） |
| 1 | 输入或校验失败：参数非法、记录与 gold 不匹配、meta 缺失、`--curve` 未提供阈值来源 |
| 2 | 配置缺失或环境不可用：`.env` 缺 key、网络失败、熔断 |

实现方式：在 `app` 入口捕获 `ValueError` → 1，捕获 `RuntimeError` → 2；
底层模块抛出的类型已按 0004 §7 约定，CLI 只做映射，不新增判定逻辑。

## 验收标准

**通用**

- [ ] `clauseproof --help` 可用，三个子命令各自的 `--help` 含参数说明与至少一个示例
- [ ] 无参数运行不抛异常，打印用法并以退出码 0 结束
- [ ] 未知子命令或非法参数 → 退出码非 0，输出可读错误

**ask**

- [ ] `--contract-id` 与 `--file` 互斥，都缺或都给 → 退出码 1
- [ ] `--clause` 支持英文原名与中文名，非法值 → 退出码 1 并列出合法取值
- [ ] 输出包含判定、置信度、路由、引用区间与文本
- [ ] 输出行数 ≤ 40
- [ ] 引用无效时显示明确提示，且路由为「转人工」

**eval**

- [ ] 产出 `<run-id>.jsonl` 与 `<run-id>.meta.json`，字段与 0002 §6/§8 一致
- [ ] 摘要包含条数、OK/失败/模糊计数、耗时、成本、平均单条耗时
- [ ] `commit` 字段来自 `git rev-parse HEAD`，失败时写 `unknown`
- [ ] 单条失败不导致命令失败（退出码 0）
- [ ] 熔断触发时退出码 2，且已有记录完整可读

**report**

- [ ] 从 meta 重建 gold；meta 缺失 → 退出码 1
- [ ] 输出分类别指标（n_total/n_decided/n_correct/accuracy/引用准确率/ECE）+ 宏平均 + 模糊率
- [ ] `--curve` 未提供 `--thresholds-from` → 退出码 1，消息说明「阈值必须在开发集上选择」
- [ ] 提供 `--thresholds-from` 时，输出与 `sweep` 在 `--run` 数据上、用来源运行阈值的结果一致

**工程**

- [ ] 测试用 `typer.testing.CliRunner`；涉及模型的命令通过 monkeypatch 注入假 judge，不发起真实请求
- [ ] `make check` 全绿

## 手动冒烟（真实调用，成本约 ¥0.1）

```bash
# 单合同演示（1 次调用）
uv run clauseproof ask --contract-id "$(uv run python -c "
from clauseproof.dataset import load_contracts
print(load_contracts()[0][0])")" --clause "Governing Law"

# 报告（读已有数据，不调用模型）
uv run clauseproof report --run results/smoke-t006.jsonl

# 曲线：用 smoke-t005 拟合阈值，在 smoke-t006 上评估
uv run clauseproof report --run results/smoke-t006.jsonl \
    --thresholds-from results/smoke-t005.jsonl \
    --curve --review-rates 0.5,0.75,1.0
```

**报告里必须包含这三条命令的真实输出**，并说明 `ask` 的输出行数。
