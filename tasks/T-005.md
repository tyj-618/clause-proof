## 序列化规则（严格照 0002 §8）

- 枚举序列化为 `.value` 字符串；反序列化时按值还原枚举
- `tuple` → JSON 数组；`None` → `null`
- `confidence` 保留 4 位小数，`latency_ms` 保留 1 位；**序列化时取整，内存中保持全精度**
- `created_at` / `started_at`：ISO 8601 UTC，形如 `2026-10-26T12:00:00Z`
- JSONL 一行一个 Record，字段顺序固定
- 元信息单独存 `<run_id>.meta.json`，不混进 JSONL

## 验收标准

**storage**

- [ ] `append_record` 后 `read_records` 能还原等值对象（浮点按取整规则相等）
- [ ] 嵌套结构（`judgment`、`spans`）完整还原，枚举还原为枚举而非字符串
- [ ] 读取空文件返回空迭代器，不抛错
- [ ] 单行损坏（非法 JSON）时抛 `RuntimeError`，消息含行号
- [ ] `write_meta` / `read_meta` 往返相等

**route**

- [ ] `present == UNCERTAIN` → 恒为 `TO_HUMAN`，与阈值无关
- [ ] `confidence >= threshold` → `AUTO_PASS`，否则 `TO_HUMAN`
- [ ] 阈值为 0 时，非模糊条目全部 `AUTO_PASS`；阈值为 1 时，仅 `confidence == 1.0` 通过
- [ ] 阈值越界（<0 或 >1）抛 `ValueError`

**runner**

- [ ] 对 N 条查询产出 N 条记录，`<run_id>.jsonl` 与 `<run_id>.meta.json` 都生成
- [ ] 每条记录含：`run_id`、`model`、`commit`、`prompt_hash`（来自 `CallMeta`），以及 `created_at`
- [ ] `judge` 返回的每个 quote 都被 `locate` 定位，`len(spans) == len(quotes)`（满足 Record 不变式）
- [ ] 记录中的 `route` 由 `apply_route` 计算，`status == OK` 时非 None
- [ ] `judge` 抛 `RuntimeError` 时，该条记为 `status=LLM_ERROR`、`error_detail` 含原文错误，
      其余条目继续处理
- [ ] 连续失败达到 `max_consecutive_failures` 时，抛 `RuntimeError` 并停止；
      已写入的记录完整可读
- [ ] `resume=True` 时跳过文件中已存在的 `query_id`，不重复调用 `judge`，
      最终记录数仍等于查询数
- [ ] `resume=False` 时清空同名文件重新开始
- [ ] 成功一条后连续失败计数归零

**关于 CONTEXT_OVERFLOW**

本任务**不实现** `CONTEXT_OVERFLOW` 的判定：当前端点上下文 1M，最长合同约 106k token，
实际不会触发。该状态保留在枚举中，等出现可识别的溢出信号（如 API 特定错误码）再接入。
所有调用失败先统一记为 `LLM_ERROR`。
