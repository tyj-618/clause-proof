## 运行方式

```bash
rm -rf .cache/llm     # 清空缓存，确保全新调用
caffeinate -dimsu uv run clauseproof eval \
    --split dev --n-contracts 50 --seed 42 \
    --run-id m1-baseline-dev --threshold 0.8
uv run clauseproof report --run results/m1-baseline-dev.jsonl
```

前置检查：`make check` 424 passed；`.env` 为 PROTOCOL=openai /
REASONING_EFFORT=low / MODEL=glm-5.3 / MAX_TOKENS=8192。
缓存核对：300/300 条 `cached=False`——全部为真实全新调用，成本与延迟未因缓存命中失真。
未使用 `--split report`，不消耗报告集配额。

## 分类别指标

accuracy 分母为 n_decided（明确判定条数）；引用准确率为 citation IoU——对每类全部
50 条的每个 gold span 取有效预测区间的最大 IoU（无有效预测记 0）后求均值。
每类 n_total=50（UNCAP_LIABILITY 含 1 条失败）。

| 条款 | n_decided | n_correct | accuracy | 95% CI | 引用 IoU | 完全包含 | 引用有效率 | 模糊 |
|---|---|---|---|---|---|---|---|---|
| Governing Law | 48 | 48 | 1.000 | [1.000, 1.000] | 0.747 | 0.283 | 0.879 | 2 |
| Cap On Liability | 36 | 29 | 0.806 | [0.667, 0.917] | 0.213 | 0.191 | 0.677 | 14 |
| Uncapped Liability | 48 | 43 | 0.896 | [0.812, 0.979] | 0.451 | 0.500 | 0.696 | 1 |
| Anti-Assignment | 46 | 46 | 1.000 | [1.000, 1.000] | 0.542 | 0.246 | 0.866 | 4 |
| Termination For Convenience | 45 | 42 | 0.933 | [0.844, 1.000] | 0.486 | 0.391 | 0.719 | 5 |
| Notice Period To Terminate Renewal | 49 | 47 | 0.959 | [0.898, 1.000] | 0.608 | 0.417 | 0.833 | 1 |

**最低的两类**：Cap On Liability（accuracy 0.806、引用 IoU 0.213）与
Uncapped Liability（0.896、0.451）——按准确率或引用准确率排序，末两位相同。

错误构成（明确判定中的 FP/FN）：

- **CAP**：FP=1 / FN=6，另 14 条模糊——以「不敢判定 + 漏判」为主，占全部 27 条
  模糊的一半以上；
- **UNCAP**：FP=4 / FN=1——以误报为主（含 INTERSECTENT 稳定假阳性，见下文）；
- **TFC**：FP=3 / FN=0——错误全部为把「协商终止」判成任意终止权，与 protocol-ab
  记录的边界问题同型，但 0.933 未成为最差类。

宏平均 0.932 为六类 accuracy 简单平均；95% CI [0.900, 0.961] 为分析时补充计算
（分类别 n_decided 内有放回重采样 1000 次、对每次重采样的六类均值取 2.5%/97.5%
分位，方法同 metrics 的分类别 CI）。全局 ECE 0.045；分类别 ECE 均为 None——每类
n_decided ≤ 49，在等频 10 桶 / min_bin_size=30 的契约下不足两个非空桶，
故校准指标只报告全局值。

## 与前两次 18 条冒烟的口径对比

冒烟（smoke-t005 / smoke-t006，各 18 条 = 3 合同 × 6 类）与本运行的关系：

- **包含关系**：冒烟的 3 份合同（RISEED / INTERSECTENT / BEYONDCOM）全部在本次
  50 份之内，18 条 query_id 逐条包含于 300 条。
- **判定一致性**：t006 与 M1 在这 18 条上 label 一致 17 条（置信度数值普遍有
  ±0.05 漂移）；唯一翻转为 `INTERSECTENT::TERMINATION_FOR_CONVENIENCE`
  （t006 present(0.75) 判错 → M1 uncertain(0.6)）。本次缓存已清空、全部全新调用，
  17/18 的 label 复现率说明端点行为接近确定。
- **稳定错误确认**：`INTERSECTENT::UNCAP_LIABILITY` 假阳性第三次出现
  （t005、t006、M1 均 present，gold=absent），维持 protocol-ab 的判断——与协议/
  档位无关，属提示词/边界问题。
- **结论是否一致**：一致。宏平均 t006 已判定口径 89%（n=14）vs M1 0.932（n=272），
  量级相同；失败率 0/18 → 1/300（网络类），openai 协议稳定性结论维持。protocol-ab
  的两个观察项：TFC 假阳性未恶化（0.933，非最差类，暂不需收紧提示词）；UNCAP
  稳定假阳性得到确认（UNCAP 为最低两类之一，FP=4/48）。

## 局限

- **dev 集**：全部数字来自开发集，与报告集分布可能不同，不能外推为最终成绩；
- **单种子**：seed=42 单次抽样，无跨种子方差信息；
- **无重复运行**：17/18 的复现率来自与冒烟的对照，非同配置重复实验；
- **阈值未调优**：threshold=0.8 为约定值，M1 是第一次正式运行、无独立阈值来源；
  复核率–准确率曲线留给 M4（dev 拟合、报告集评估，消耗一次报告集配额）；
- 分类别 95% CI 较宽（如 CAP [0.667, 0.917]），单类结论需谨慎；bootstrap CI 只
  覆盖本批数据的抽样噪声，不覆盖模型/端点的时变波动。

## 引用定位修复（T-011a，2026-10-29）

M1 报告完成后对引用失败的分析与离线修复。判定类指标不受影响，本节数字
除注明外均为 span 级口径。

- **问题**：223 条引用中仅 179 条（80.3%）能精确匹配原文。
- **诊断**：35 条仅差空白（CUAD 原文含连续空格，模型复制时归一化为单空格）、
  7 条截断、2 条真正改写；根因在 locate 只做精确匹配，不在模型。
- **修复**：locate 改为三层匹配（精确 → 空白归一化 → 失败）；归一化命中的
  区间通过位置索引 `pos[]` 映射回原文（保留原文连续空白）；`Span` 增加
  `matched` 字段（exact / normalized / none）区分来源，并新增
  `citation_exact_rate` 指标。契约同步：设计 0002 v0.4、0003 v0.9。
- **结果**（`results/m1-baseline-dev.spans-v2.jsonl`）：

  | 指标 | 修复前 | 修复后 |
  |---|---|---|
  | 引用有效率 | 80.3%（179/223 exact） | 96.0%（179 exact + 35 normalized） |
  | 引用 IoU 宏平均 | 0.508 | 0.615 |
  | 判定类指标（宏平均 / 模糊率 / 全局 ECE） | 0.932 / 9.0% / 0.045 | 全部不变（重算只影响引用） |

  分类别 IoU：GL 0.747→0.876 · CAP 0.213→0.282 · UNCAP 0.451→0.701 ·
  AA 0.542→0.613 · TFC 0.486→0.610 · NPTTR 0.608→0.608（该类新命中的
  span 不与 gold 重叠）。
- **遗留**：Cap On Liability 修复后仍仅 0.282——问题在引用质量（模型选段）
  而非定位，是后续改进方向。
- **说明**：迁移用 `scripts/recompute_spans.py` 离线重算，未调用模型，成本 ¥0；
  原始 JSONL 保留未改，修正版为独立文件（`m1-baseline-dev.spans-v2.jsonl`

## M4 曲线：拟合/评估分组（T-012，2026-10-29）

原计划 M4 为「dev 拟合、报告集评估」并消耗一次报告集配额（见上文「局限」）；
本节为零成本替代：用已有的 300 条记录按合同拆分，不调用模型、不消耗报告集配额。

**拆分**（`scripts/split_by_contract.py`，从 `m1-baseline-dev.spans-v2.jsonl` 派生）：
按 `sha256(contract_id)` 取模 2 把 50 份合同分成互斥两组——

| 组 | run_id | 合同 | 记录 |
|---|---|---|---|
| 拟合组 | m1-fit | 23 份 | 138 条 |
| 评估组 | m1-eval | 27 份 | 162 条 |

两组 meta 仅 `run_id` 不同，`split` / `n_contracts` / `seed` / `n_queries` 保持
原值（report 靠这几个字段重建 gold）；记录全部字段原样保留。评估组含全部
300 条中唯一一条失败记录（`REWALKROBOTICSLTD…::UNCAP_LIABILITY`，网络类）。

```bash
uv run clauseproof report --run results/m1-eval.jsonl \
    --thresholds-from results/m1-fit.jsonl \
    --curve --review-rates 0.15,0.3,0.45,0.6,0.75,1.0
```

评估组自身指标：宏平均 0.924 · 模糊率 10.5%（17/162）· 全局 ECE 0.061。
曲线输出（阈值拟合自 m1-fit，评估于 m1-eval）：

| 目标复核率 | 实际复核率 | 自动通过准确率 | 复核后准确率 |
|---|---|---|---|
| 0.150 | 0.160 | 0.926 | 0.938 |
| 0.300 | 0.302 | 0.965 | 0.975 |
| 0.450 | 0.469 | 0.977 | 0.988 |
| 0.600 | 0.556 | 0.972 | 0.988 |
| 0.750 | 0.747 | 0.951 | 0.988 |
| 1.000 | 0.969 | 1.000 | 1.000 |

口径：自动通过准确率 = 评估组自动通过条目中判对的比例；复核后准确率 =
1 −（自动通过且判错）/ 全部，即假设转人工条目均被人工纠正后的整体准确率。

**性质与局限**：

- 拟合组与评估组是**互斥合同**（无交集，合并恰为原 50 份）：阈值只在拟合组上
  用 gold 选择、在评估组上统计 —— 这是留出验证，不是同批拟合；
- 实际复核率会偏离目标（如 0.15 档实际 0.160）：阈值在拟合组上约束复核率，
  应用到评估组后分布不同；目标 1.0 时实际 0.969，因 confidence 恰为 1.0 的
  记录按 `>=` 语义仍自动通过（0003 §3 已知边界）；
- 样本量（评估组 162 条）仍然偏小，曲线只作趋势参考；
- 本节不消耗报告集配额，也不替代报告集上的最终评估。
