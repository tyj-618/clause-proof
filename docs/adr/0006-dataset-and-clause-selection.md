# ADR-0006：数据源与条款范围的选择

- 状态：Accepted（2026-10-26 补记，决策发生于 2026-10-20）
- 日期：2026-10-26
- 决策者：Owner + Tech Lead
- 关联：[PROJECT.md](../../PROJECT.md) §2、§4、[PRD-0001](../prd/0001-contract-clause-review.md) §3

## 背景

选题的三条依据（PROJECT §2）：任务必须客观可验证、数据必须自包含、必须存在真实的工程难点。数据源与条款范围的选择同时决定「能不能自动评分」和「结论能外推多远」。

## 决策

1. **选 CUAD v1 作为数据源**：`CUAD_v1.json`（38MB）内含 510 份合同全文，无需 PDF 解析、OCR 或额外 txt；13,823 条 span 标注**100% 精确匹配原文**、可回原文逐字校验（PROJECT §4，核验时间 2026-10-19）。引用评测因此是算术问题而非判断题，不需要 LLM 当裁判。
2. **从 CUAD 的 41 个条款检查项中选 6 类边界清晰的条款**：Governing Law、Cap On Liability、Uncapped Liability、Anti-Assignment、Termination For Convenience、Notice Period To Terminate Renewal（510 × 6 = 3060 条查询，PRD FR-1）。选择标准是「**存在性判定边界清晰 + 输出可回原文校验**」，不是「法律上最重要」（PRD 3.1）；每类在 PRD 3.2 有三态（有 / 无 / 模糊）判定边界表。
3. **排除 5 个 License 细分类**：它们语义互相重叠，存在性判定会串（PRD 3.1、§4 非目标；PROJECT §6）。
4. 范围事实（决定评测复杂度）：六类有答案比例 86% / 54% / 22% / 73% / 36% / 22%（PRD 3.1），正负样本高度不均衡；Cap On Liability 与 Uncapped Liability 在数据上不互斥——111 份含 Uncapped 的合同全部同时含 Cap（PRD 3.3），两者须独立判定。

## 后果

**正面**

- 数据自包含（单一 JSON 文件），复现不依赖外部解析环境（NFR-7）
- 存在性判定可三态化，且每类有明确的判定边界，机器评分可行
- gold span 全量可回验，引用准确率、失效率全部可自动计算

**负面**

- 范围限于 6 / 41 类条款，结论不能外推到全部检查项，更不能外推到「合同审阅」整体
- 类别不均衡（22%–86%）是数据事实，评测必须承担分类别报告 + 宏平均的复杂度
- CUAD 为英文合同，跨语言列为 future work（PROJECT §6）

**风险**

- Cap 与 Uncapped 的不互斥关系容易被实现侧误设为互斥假设，造成系统性出错；判定边界文档必须保持两者独立（PRD 3.3 已明确「不需要冲突检测」）

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 需要 OCR 的收据 / 票据类数据集 | OCR 引入解析误差，eval 不稳：引用是否「真的在原文里」取决于 OCR 质量而非模型，破坏「可回原文校验」的根基（PROJECT §2 数据必须自包含） |
| 自建数据 | 标注可信度打折：缺少 CUAD 这种 13,823 条 100% 可回验 span 的客观基础，「引用可自动评分」无从谈起，评测说服力退化为对标注者的信任 |
