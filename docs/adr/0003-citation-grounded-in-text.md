# ADR-0003：引用以声称文本为准，字符偏移由系统定位

- 状态：Accepted（2026-10-26 补记，决策发生于 2026-10-20）
- 日期：2026-10-26
- 决策者：Owner + Tech Lead
- 关联：[设计 0002](../design/0002-data-model.md) §3、[设计 0003](../design/0003-interfaces.md) §2–§3、[PRD-0001](../prd/0001-contract-clause-review.md) FR-2 / FR-3

## 背景

PRD FR-2 要求判定为「存在」时必须给出可回原文定位的引用；FR-3 要求该检查**不依赖 gold span**。设计时的核心取舍：引用的「锚」——字符偏移——放在模型侧还是系统侧？

## 决策

1. **模型只输出它声称摘录的原文片段（`quotes`），不输出字符偏移。**`Judgment` 的字段为 `present` / `quotes` / `confidence` / `raw_output` / `parse_ok`（设计 0002 §3），没有任何偏移字段。
2. **偏移由系统在原文中精确查找得出。**`locate(quotes, text)` 是纯函数：`start = text.find(quote)`、`end = start + len(quote)`、`occurrences = text.count(quote)`（设计 0003 §2），产出 `Span`（`quote` / `start` / `end` / `valid` / `occurrences`，设计 0002 §3）。
3. **定位失败不丢弃**：失败的 quote 保留原文与 `valid=False` 标记，引用有效率 = 有效 quote 数 ÷ 全部 quote 数（PRD FR-3）——失效率本身是要统计与优化的指标。
4. **核心理由**：若模型直接给偏移，自检「`原文[start:end] == 模型给的文本`」**恒为真**——切片本来就是按同一对偏移取出来的，等于没验。把偏移交回系统，模型输出的每个字都必须真的出现在原文里，引用才算有效。
5. **该设计是「引用可自动评分」的前提**：CUAD 的 13,823 条 gold span 100% 精确匹配原文（PROJECT §4），gold 与预测都是字符区间，引用准确率（IoU / 完全包含）才是算术比较，无需 LLM 当裁判（PROJECT §2「任务必须客观可验证」）。

> PRD 0.2 变更记录（2026-10-20）明确登记了这次口径切换：「引用改为『声称文本 + 系统定位』」。

## 后果

**正面**

- 引用有效性成为可离线复算的指标：仅凭落盘记录即可重算，无需重新调用模型（FR-3）
- 模型无法「假装引用」：改写一个标点都会让精确查找失败并计入失效率
- 模型职责被压到最小（判定 + 摘录 + 置信度），流水线其余环节全部可测

**负面**

- 同一段文字多次出现时「只取首次出现」可能与 gold 错配（PRD 开放问题 Q6），或系统性低估引用准确率
- 模型输出的微小改写（空格、标点、省略号）即定位失败，引用有效率承受全部压力，需要专门优化提示词

**风险**

- quote 与 gold 表述一致但区间边界不同（多引一句 / 少引一句）时 IoU 会惩罚；IoU 阈值 τ 尚未确定（开放问题 Q3），且一经确定即冻结沿用，选错会长期影响口径

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 模型直接输出 start / end | 自检「原文[start:end] == quote」恒为真，形同虚设；且「偏移数错」与「真引用但措辞改写」两种失败无法区分，失效率失去解释力 |
| 用另一个 LLM 判定引用是否正确 | 不可复现（评测依赖「另一个模型说好不好」，违背 PROJECT §2 客观可验证原则）、成本翻倍、裁判自身的误差进入指标 |
